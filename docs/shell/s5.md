# S5: bash, and scripts run by their type

Phase S5 of the shell ([design.md](design.md)).

| Step | What | State |
|---|---|---|
| 1 | `execve` of a script: `#!`, and `/etc/vibeos/binfmt` by extension | done |
| 2 | bash built against musl, at `/usr/bin/bash`, and `.sh` pointed at it | to do |

## Step 1

Until this step `execve` knew only programs: a script was refused as an image
it could not load, with `ENOMEM`.

- **`#!`** follows Linux: the interpreter, then everything after it as *one*
  argument, then the path the caller gave, then the caller's arguments. A
  script's interpreter may be a script, four deep; past that `ELOOP`.
- **The table** has lines `.ext /path/to/interpreter`, compared ignoring case.
  A `#!` wins when there is one. `.vsh` runs vsh and `.sh` runs `/bin/sh`, which
  is BusyBox's until step 2. `.bat` and `.cmd` arrive with S6.
- A file that is neither a program nor a script is `ENOEXEC`, which is what
  tells a POSIX shell to try it as a script itself.
- The interpreter is asked the same questions as a program: search permission,
  the execute bit, and a mount without `noexec`.

The rules are `kernel/exec/script.c`, shared by every personality. The test is
`tests/linux/musl_script.c`, which is its own interpreter and runs on Linux and
at every boot; the gate fails `script_exec_failed:<which>`. Case:
`exec-script.txt`.
