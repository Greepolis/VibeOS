# Names and metadata, docs/abi/ L1 step 5 (kernel/abi/linux/names.c), proved by
# the handlers' host tests in tests/kernel/linux_abi_tests.c.
#
# Each case names the expectation it should fail. The handlers decide what
# Linux decides before a filesystem is asked, and tmpfs decides some of the
# same things again for itself - so a case that removes only the handler's
# check can be caught by the filesystem under it. Where that happened it is
# said at the case.
#
# Two went NOT RED on their first run for exactly that reason - NOREPLACE left
# to the filesystem, and an empty symlink target - because tmpfs refuses both
# itself. The handler's check is what makes a filesystem that cannot rename or
# link at all give Linux's answer (EEXIST, ENOENT) rather than its own (EPERM),
# so both are asked of the fake kernel's root now, which can do neither.
#
# Target source: kernel/abi/linux/names.c
# Run: SABOTAGE_VERIFY="bash scripts/dev/verify-host.sh build-gcc-Release" python3 scripts/dev/sabotage.py kernel/abi/linux/names.c scripts/dev/cases/abi-names.txt
