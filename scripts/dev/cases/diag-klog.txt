# C6: the kernel log (kernel/diag/klog.c), proved by the host test.
#
# The three docs/core/phases.md names for C6 - an unmatched unlock, a multi-part
# message left unbracketed, a sink that drops a line silently - plus the defects
# that moving the log out of arch_hw.c found and closed. Each breaks one rule and
# the run must go red on the host test that names it:
#  1. an unlock with no lock behind it: on the console lock this freed another
#     core's line mid-word and the gate reported crashes that had not happened;
#  2. a line handed to a sink in two writes: two critical sections, and the
#     marker between them gets cut;
#  3. a sink's refusal ignored: the line is gone and nothing says so;
#  4. the ring recorded without its lock: two cores claim one slot;
#  5. the event printed is "the latest" asked for after the lock is dropped: with
#     two cores logging, one line twice and the other never - what hw_log did;
#  6. a sink written under the ring's lock: every logging core waits on the UART;
#  7. the reentrancy guard gone: a disk sink whose block layer logs would recurse;
#  8. one line counter shared by all sinks: a gap in one hides behind the other.
#
# The serial sink's own honesty - that it wrote what it said it wrote - cannot be
# seen from here; diag-sink.txt breaks it and the boot gate's ln= check
# catches it.
#
# Target source: kernel/diag/klog.c
# Run: python3 scripts/dev/sabotage.py kernel/diag/klog.c scripts/dev/cases/diag-klog.txt build-clang-Release
