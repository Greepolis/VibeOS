# held to e2fsck, to the bytes the same changes make here, and to the free
# counts of an empty volume. And by the torture, which has every file with an
# index level go through the window.
#

# Not a case, and why. Leaving the root's key for an index block as it was
# went NOT RED, correctly: that key moves only if something is put in front of
# the index block's first extent, and a write into the hole before it is routed
# to the index block before - the root picks the last key at or below the
# block written. The update stays as the rule Linux keeps; this file cannot
# make it matter.
