# The ext4 writer (kernel/fs/ext4_write.c, docs/filesystem-design/ext4.md step 2),
# broken; caught by scripts/dev/verify-ext4.sh, which applies a script of changes
# through the driver to volumes mkfs.ext4 made, asks e2fsck -fn whether the
# result is clean, has debugfs read it back out and holds that against the
# host's own copy of the tree.
#
# Each case takes away one thing the format keeps true, so a red result says the
# oracle - somebody else's checker, or a tree the host built - sees it. Where the
# driver's own reader notices first (it checks every checksum it reads), that is
# the red; the case still proves the checksum is one the writer must produce.
#
# Target source: kernel/fs/ext4_write.c
# Run: SABOTAGE_VERIFY="bash -c 'cmake --build build-gcc-Release --target vibeos_ext4_exercise > /dev/null && bash scripts/dev/verify-ext4.sh build-gcc-Release'" python3 scripts/dev/sabotage.py kernel/fs/ext4_write.c scripts/dev/cases/ext4-write.txt build-gcc-Release
