# One descriptor table per process, shared by its threads (2026-09-27). The
# table lives in hw_procstate_t; a thread is one more user of it, fork and exec
# take a copy. Run with SABOTAGE_VERIFY=scripts/dev/verify-boot.sh.
#
#  1. clone does not count the thread as a user of the table. Expect
#     task_files_double_leave. It was first written expecting
#     thread_descriptors_not_shared and went NOT RED: the first thread the
#     threads test ever creates takes the count to zero - closing a table that
#     held nothing yet - and every later exit wraps it, so by THREADS_C5_FILES
#     nothing closes anything. The symptom shows once, somewhere arbitrary; the
#     underflow shows every time, so that is what is gated.
#  2. exec does not copy the table into the new process. Every redirection a
#     shell set up before exec is gone. Observed: the boot wedges at
#     phase=selftest_done (missing:CLI_READY) - the programs the self-test
#     script starts have no descriptors at all. Since A3, 0-2 are table
#     entries too, so an exec'd program has not even the console: re-run on
#     2026-09-30 the boot wedges earlier (missing:VIBEOS_SELFTEST_DONE), with
#     only init - which the kernel starts, console installed - writing at all.
#
# Not a case: the table's lock. Two threads claiming the same slot at once needs
# them to meet inside a few instructions, which one boot does not arrange; a
# case that went NOT RED would say nothing about the lock. Recorded as untested.
