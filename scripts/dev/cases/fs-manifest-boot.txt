# The mount manifest on the machine (hierarchy F2 step 3): the boot disk's
# root carries /etc/vibeos/mounts, the ESP named in it by UUID, and the kernel
# mounts what it says.
#
#  1. The manifest is not found: the kernel falls back to its built-in
#     default. Expect manifest_not_from_root - the default mounts the same
#     places, so nothing else notices.
#  2. The log names the ESP's line by something other than its UUID. Expect
#     esp_not_mounted_by_uuid.
#  3. A filesystem type check that refuses what it should accept: the ESP's
#     line fails, and it is required. Expect required_mount_failed (and the
#     ESP missing from /boot/efi).
#
# Target source: kernel/arch/x86_64/io_bringup.c
# Run: SABOTAGE_VERIFY="bash scripts/dev/verify-boot.sh build-gcc-Release" python3 scripts/dev/sabotage.py kernel/arch/x86_64/io_bringup.c scripts/dev/cases/fs-manifest-boot.txt build-gcc-Release
