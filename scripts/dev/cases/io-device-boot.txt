# C7: the device registry on the machine (kernel/arch/x86_64/arch_hw.c), proved by
# the boot gate. What no host test can see: the linker section, the interrupt
# routing and the wake-up that the registry now drives.
#
#  1. the table the linker collected is ignored - a kernel with no devices.
#     Expect missing:CLI_READY verdict=boot_volume_missing: with no disk driver
#     there is no boot volume, which the kernel now says (BOOT_VOLUME_FAIL), and
#     with no keyboard the boot's own script is never typed, so the boot stops
#     before the counters that would name the table (device_table_short) are
#     printed. It was verdict=guest_wedged until the kernel said so;
#  2. an input interrupt no longer wakes whoever is blocked reading the console:
#     expect input_irq_wake_unproven;
#  3. the legacy lines are not routed, so the keyboard and the mouse never
#     interrupt: expect kbd_irq_unproven.
#  4. only the first disk is bound (step 3): the log disk and the boot disk
#     are on different controllers, so the loop stopping after one loses a
#     medium the boot needs. Expect verdict=boot_volume_missing with
#     stage_failures=BOOT_VOLUME_FAIL. It first went red as a wedge
#     (missing:VIBEOS_SELFTEST_DONE verdict=guest_wedged), and the log showed it
#     was not one: the kernel said "boot volume on none", ran the built-in init
#     and sat at its prompt, while the gate waited for a self-test that lives
#     on the missing disk. The kernel now says BOOT_VOLUME_FAIL and the gate
#     names the verdict.
#
# The first run of 2 and 3 went NOT RED. Nobody types in CI - the boot's script
# is injected into the keyboard's ring, which raises no interrupt - so the IRQ1
# path ran in no boot at all. The keyboard's probe now makes the PS/2 controller
# raise IRQ1 (command 0xD2, a key-release byte the driver ignores) and the gate
# asserts that it arrived and woke a reader. device_counters_missing is the
# [DEV] line disappearing.
#
# Target source: kernel/arch/x86_64/arch_hw.c
# Run: SABOTAGE_VERIFY="bash scripts/dev/verify-boot.sh" python3 scripts/dev/sabotage.py kernel/arch/x86_64/arch_hw.c scripts/dev/cases/io-device-boot.txt
