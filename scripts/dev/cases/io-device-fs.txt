# C7 step 3b: FAT as a filesystem driver that declares itself
# (kernel/arch/x86_64/fat_vfs.c, VIBEOS_FS_DRIVER), proved by the boot gate.
# The storage table's own rules - whole-name lookup, a driver without a mount
# refused - are host cases in storage.txt.
#
#  1. the driver does not declare itself: nothing registers FAT, the boot volume
#     has no driver to mount it and the boot must go red rather than run on
#     without a root. Expect verdict=boot_volume_missing (it was a "wedge"
#     until the kernel said BOOT_VOLUME_FAIL - see io-device-boot.txt case 4);
#  2. the driver's mount ignores the volume it is given and mounts the boot
#     volume: the formatting exercise now reaches FAT through the registry
#     rather than through fat_ops and fat_mount_volume, and a path under /vol1
#     reading back the root is exactly what its read-back exists to catch.
#
# Target source: kernel/arch/x86_64/fat_vfs.c
# Run: SABOTAGE_VERIFY="bash scripts/dev/verify-boot.sh" python3 scripts/dev/sabotage.py kernel/arch/x86_64/fat_vfs.c scripts/dev/cases/io-device-fs.txt
