# C5: the pipe module (kernel/ipc/pipe.c), proved by the host test.
#
# A pipe hangs a shell when a count is wrong, and it corrupts a stream when the ring
# is. Each case breaks one rule and the run must go red on the host test that names it:
#  1. end of file is reported whenever the pipe is empty, without asking whether a
#     writer remains: `ls | wc -l` would print nothing;
#  2. a pipe is freed when *either* end is gone: a reader loses bytes a writer wrote
#     just before it closed;
#  3. a release with nothing to release is clamped away, as the old code did, instead
#     of counted: the wrong count stays invisible until a pipeline hangs;
#  4. writing with no reader is accepted: the bytes are taken for nobody and no
#     SIGPIPE is raised.
#
# Target source: kernel/ipc/pipe.c
# Run: python3 scripts/dev/sabotage.py kernel/ipc/pipe.c scripts/dev/cases/ipc-pipe.txt build-clang-Release
