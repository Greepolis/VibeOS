# M-056: the swap-out protocol (kernel/mm/vmspace.c), proved by the host test's
# swap-out groups in tests/kernel/compact_tests.c, whose in-memory disk runs
# "another core" in the middle of the page's write.
#
# A swap-out keeps the page present and readable while it is written, takes a
# writable page's write bit and marks it, and commits with one compare-exchange
# from exactly that marked entry. Anything that touched the entry in between
# makes the exchange fail and the swap-out is abandoned.
#
#  1. the commit is a plain store: a store that cancelled, an mprotect, an
#     munmap and a fork are all overwritten - the page goes to swap with the
#     cancelled store's write lost, or a freed entry is written over;
#  2. the write bit is taken without the marker: a store in the middle is then
#     a protection violation, and a program is killed for writing its own page;
#  3. the fault does not cancel: the same, from the other side;
#  4. mprotect keeps the marker: a page made read-only would have its write bit
#     "given back" on the next store - the bit-9 defect CLAUDE.md records;
#  5. fork shares a marked page as it stands: both copies read-only and not
#     copy-on-write, and the child killed on its first store;
#  6. a read-only page is marked too: the marker would promise a write bit it
#     never had.
#
# Target source: kernel/mm/vmspace.c
# Run: python3 scripts/dev/sabotage.py kernel/mm/vmspace.c scripts/dev/cases/mm-swapout-protocol.txt
