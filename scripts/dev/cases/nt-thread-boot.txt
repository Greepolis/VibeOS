# NT threads at boot (docs/abi/windows.md W5 step 1): hello.exe creates a
# thread that stores what it was given and its own TEB's address, waits for it,
# and checks both (thread_check). The two rules here live on the machine side
# of ksvc.h, where the fake kernel cannot show them - its tasks all speak Linux
# and it has no %gs register.
#
#  1. a thread speaks Linux, not its process's personality: its NtTerminateThread
#     is a Linux number and comes back, and the thread never ends. Expect
#     guest_wedged with a core in vibeos_nt_process_start.
#  2. setting a new thread's %gs writes its creator's register: both read the
#     child's TEB. Expect nt_program_did_not_run=thread_teb.
#
# Target source: kernel/arch/x86_64/ksvc.c
# Run: SABOTAGE_VERIFY="bash scripts/dev/verify-boot.sh" python3 scripts/dev/sabotage.py kernel/arch/x86_64/ksvc.c scripts/dev/cases/nt-thread-boot.txt build-gcc-Release
