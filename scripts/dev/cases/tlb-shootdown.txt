# What each case actually caught, since it is not what you would guess:
#
#   - removing fork's shootdown was caught by the boot's *counter* (and TFORK.ELF's
#     opportunistic data check only sometimes) until munmap and mprotect began
#     issuing shootdowns of their own: the counter then stayed non-zero without
#     fork's, and this case went from red to NOT RED without anyone noticing. It is
#     now caught deterministically by the host test, which records what the layer
#     asks the backend for and requires a shootdown of the *source* address space.
#   - not waiting for the acknowledgement wedges the boot outright.
#   - sending to every core instead of only those running this address space
#     does not corrupt anything; it stalls. `syscall` clears IF, so a core in
#     a syscall cannot answer until it returns to ring 3, and waiting on cores
#     with no stake in the mapping was the first version of this code. It timed
#     out about three boots in thirty-two.
#
# Since the first load that forced reclaim (M-063 era), the shootdown chooses
# its targets by what is in each core's CR3 rather than by its current task,
# waits per target on cr3_generation instead of a machine-wide count, and a core
# waiting with interrupts off answers flush requests addressed to it. Two of
# those are races with no deterministic case: a teardown waiting for a reclaim
# claim on a core the swap-out targets (the deadlock that stopped the machine),
# and two shootdowns wiping each other's count. They are argued in the source.
# "Nobody waits" now reads as tlb_flushed below tlb_targets.
#
# "Goes to every core" is NOT RED now, and that is correct: broadcasting only
# costs waiting on cores with nothing to flush. Its earlier red - faults and
# swap_double_free=6 - was the page-in's stale-slot race (M-063), which the
# broadcast's timing happened to open; with that fixed, the sabotage is slower
# and not wrong, which is what this case always claimed.
#
# "Fork never tells the other cores" anchors in kernel/mm/vmspace.c and reads
# "anchor not found" when this file is run against arch_hw.c; run it against
# vmspace.c for that case.
